Overview

This challenge runs in 6 phases, each providing a slow x86-64 ELF file (prog-N). Your goal is to modify or rewrite these program so they produce the same output as the original but complete in under 3 seconds. The faster your solution, the higher your score.

How the Competition Works

  • Every 5 minutes (a “tick”), your latest submission is tested with a random input.
  • If your program finishes correctly within 3 seconds, you earn points.
  • Each phase’s program is retired after that phase ends.

Upload & Evaluation

Upload
  1. Download prog-N and test.py via Dashboard
  2. Reverse engineer the program and improve the speed.
  3. Use the provided test.py to run some simple tests.
  4. Upload your modified prog-N through Dashboard.
Evaluation
  • Your program must read from stdin and write to stdout.
  • Your program must finish in under 3 seconds.
  • The output must match what the original program would produce if it ran with unlimited time and resource.
  • Only standard output is checked.
  • You can check the result in Scoreboard.
  • All test cases are guaranteed to be valid - they will not trigger undefined behavior such as arithmetic overflows or out-of-bounds memory access.
Timing & Scoring
  • For each tick, your program is run 20 times using the same test case.
  • If any of these execution times out or the output is incorrect, it fails.
  • The official speed is the median of these 20 runs.
  • The execution time is rounded to one decimal place (e.g. 1.3s), with rounding to the nearest 0.1s.
  • If the program finishes execution within 3 seconds, the subsequent time taken to read from stdout is not counted towards the execution time limit, meaning the final evaluation time may exceed 3 seconds.
  • Inputs become more challenging as ticks progress. (Check Dashboard for the testcase difficulty)
  • Scores are assigned based on ranking as follows.

Test Environment

  • Host: Ubuntu 24.04 LTS (No external library is installed.)
  • CPU: Up to {{ config.game.isolation.cores_per_team }} cores (out of 20 total) per run (See "CPU Model" section for more details)
  • Memory: {{ config.game.isolation.memory }} MB limit per run (-m 256m)
  • Process: Guaranteed to spawn up to 3 processes (--pids-limit={{ config.game.isolation.max_pids }})
  • Network: No external network access (--network=none)
  • Capability: No capability (--cap-drop=ALL)
  • Cache: Not dropped between runs.
  • Temporary directory (/tmp) is available.
  • All teams' programs run in parallel but on different cores.
